# ADOFAI Editor Studio

《冰与火之舞》编辑器工作台 mod。在游戏关卡编辑器之上叠加一层工作台，提供**不进入游玩状态**的实时预览、时间轴浏览和事件参数编辑。

当前版本 **0.33.2**，处于**开发中**：预览、浏览、装饰物编辑与联机做谱可用（见「尚未完成」）。

## 界面

界面由 **Dear ImGui** 绘制（0.31.0 起）。**面板的位置和大小仍由原来的 uGUI 布局计算**，ImGui 只负责画出来和收输入 —— 所以外观、位置、响应式行为都没变，换掉的是渲染层。

这么做是因为这类密集的工具界面用 uGUI 拼太贵：一个控件就是一个 GameObject，改一次布局整块 Canvas 都要重建。ImGui 是立即模式，每帧直接画，面板重排不再触发重建。

面板逐个迁移，目前覆盖：参数栏、时间轴、装饰物列表、媒体区、预览面板、顶栏、帮助。

## 环境要求

- 《A Dance of Fire and Ice》（Steam 版）
- Unity Mod Manager `0.32.5`
- 无其他依赖（不需要 JALib）

## 安装

把压缩包里的 `ADOFAIEditorStudio` 文件夹整个放进游戏的 `Mods` 目录：

```
<游戏目录>/Mods/ADOFAIEditorStudio/
├── Info.json
├── ADOFAIEditorStudio.dll     ← mod 本体
├── cimgui.dll                 ← ImGui 原生库
├── ImGui.NET.dll              ← ImGui 托管包装
├── UiFont.ttf                 ← 界面字体
├── UiFont-LICENSE.txt         ← 字体许可证
├── README.md
└── LICENSE
```

`Mods` 目录通常在：

```
<Steam 库>/steamapps/common/A Dance of Fire and Ice/Mods/
```

启动游戏，在 Unity Mod Manager 中确认 mod 已加载（显示「ADOFAI Editor Studio」）。

## 自动更新

**启动时会检查更新，发现新版就自动下载、替换。装好后需要你关掉游戏再打开一次。**

- 版本低于要求 → 自动下载 → 覆盖 → **提示你重开游戏**，重开后就是新版
- 已是最新 → 什么都不做
- **读不到更新信息（断网、源不可用）→ 照常运行**，只记一条日志

装好之后日志里会出现这一行，看到它就可以关掉重开了：

```
[Update] 已装好 x.y.z。请关闭并重新打开游戏以生效。
```

**为什么不自动重启**：试过五种重启方式，都会在真实环境下起出一个卡住的实例（游戏能进，但所有 mod 都不加载）。安装本身是可靠的，只有"重启"这一步不可靠，所以交给用户点两下。

更新走 GitHub，国内网络可能不稳。**连不上不影响使用**，但也不会自动升级 —— 那种情况请到群里手动下载最新包。

QQ 群：**1105868183**

## 使用

1. 进入游戏的关卡编辑器，打开一张谱面
2. 按 **F8** 打开工作台
3. 按 **Esc** 关闭

工作台接管渲染：画面由 mod 自己的求值器逐帧计算，**不调用游戏原有的 `Play()`**，因此可以任意拖动时间轴而不会触发读秒、判定或游戏状态变化。

## 已实现

**预览**

- 独立的绝对时间求值器，覆盖 15 类事件域：轨道移动与轨道动画、镜头、轨道上色、装饰物、闪烁、泛光、自定义背景、屏幕平铺、屏幕滚动、镜像、震屏、滤镜、高级滤镜、粒子、行星（球）
- 复现原版的「球踩过的格会点亮」——轨道的辉度只在已点亮的格上渲染，不补这一步辉度永远看不见
- 行星预览：位置、旋转角度、角速度、红蓝配色、尾焰拖尾；双球与**三球**的角色交接、长按格的滑移（含球的小幅摆动与长按线的填色）、**freeroam 自由移动段**（网格、原地转动、出场渐隐与运镜），以及镜头在长按与 freeroam 出场期间的跟随
- 效果数学对齐游戏本体，而非近似：每个域都对照反编译源码或实测数据校准过
- 拖动时间轴时逐帧求值；基准为绝对时间，不依赖拖动方向

**时间轴**

- 读取真实谱面事件，分为镜头、视效、装饰、音频、游戏、其他六类
- 按事件类型分色，同类型优先同水平线排布
- 缩放（`Ctrl + 加号/减号`、`Ctrl+滚轮`）、行高调整（`Alt + 加号/减号`、`Alt+滚轮`）
- 拖动顶部细条调整时间轴面板高度
- 滚轮纵向浏览，`Shift+滚轮`横向浏览，中键拖动平移
- 点击事件块选中，与游戏原生选择联动；`Ctrl+点击` 加选、在画面里框选可以多选
- 多选后直接在参数栏批量改值：共同属性一次写进所有选中事件，取值不一致的键显示为「混选」，不去动它
- `Ctrl+C` 复制 / `Ctrl+X` 剪切 / `Ctrl+V` 粘到**播放头所在格**
- 面板高度变化时自动重排，事件标记数量与行高自适应
- 左侧为装饰物列表（见下）

**参数栏**

- 选中时间轴上的事件块后，右侧列出该事件的可编辑属性
- 参数表由**游戏自身的属性元数据**生成，不是手工维护的表，因此新事件类型无需改动代码即可显示
- 支持控件：开关、整数、浮点、文本、枚举、二维向量、颜色（色块 + 十六进制 + 可视化取色器）
- 属性名跟随游戏语言（中文客户端显示中文）
- 装饰物事件顶部显示对应的装饰物图片
- 每个事件可以标「生效 / 不生效」，不生效的块在时间轴上变暗
- 面板变窄时双输入框自动改为上下排列
- 输入框有可见光标与聚焦高亮

**装饰物编辑**

- 从左侧媒体区**拖动图片到画面**即可新建装饰物，跟随鼠标落点
- 拖动中调整：滚轮缩放、`Alt+滚轮`旋转、`Ctrl+滚轮`透明度、`Shift+滚轮`深度、`Ctrl+Shift+滚轮`平行（视差）
- 顶部状态栏实时显示当前调整值
- 松手在画面内保留；拖回左侧或松手在画面外取消
- 拖动已有装饰物改位置（写入当前帧关键帧）

**撤销 / 重做**

- `Ctrl+Z` 撤销、`Ctrl+Y` 或 `Ctrl+Shift+Z` 重做
- 覆盖：新建装饰物、删除装饰物、拖动装饰物、参数栏改值、装饰物显隐与锁定
- 工作台维护自己的撤销栈，**与 PACL2 共存**；未接管的操作回退到游戏原生撤销

**视图锁**

- 时间轴上的锁形按钮：一键同时锁定**镜头位置**与**缩放**
- 锁定后拖动画面或滚轮缩放会立即弹回谱面原本的取景
- 状态随设置保存

**性能**

- 关闭工作台时不影响游戏
- 大谱面下跳过"全透明装饰物"的逐帧写入；在 1253 个装饰物的谱面上从 20 帧提升到 70 帧以上
- 0.10.9 修掉了一个严重的周期性卡顿：几处诊断日志在**正常播放路径上无条件写入**。
  UMM 的日志内部是同步 `Console.WriteLine`，游戏带控制台启动时每次都是一次真正的
  阻塞式控制台写入，单条实测占掉过一整帧 **176ms**；其中 `[SyncTrace]` 失步时
  会一次灌 240 行。这造成每 0.4~1.3 秒一次的可见卡顿，重谱上因为失步更频繁而更明显。
  现已全部挂上 `VerboseDiagnostics` 门控，默认不产生任何输出

**媒体区**

- 自动索引谱面目录（含子目录）内的 PNG/JPG/JPEG/GIF，六列缩略图网格
- **搜索**与**刷新**，按修改时间倒序（新图在前）
- 从媒体格直接拖到画面即可新建装饰物
- 不写任何附属文件；索引每次扫盘得出

**装饰物列表**

- 时间轴左侧列出当前谱面所有装饰物，点击选中（右侧参数栏跟随）
- 每行显示图片文件名、tag、类型图标，以及**隐藏 / 锁定 / 删除**三个操作
- 可按名字、tag、类型、所在格搜索（支持 `tag:` / `type:` / `floor:` 前缀）
- 顶部四个按钮新建图片 / 文本 / 粒子 / 对象装饰物
- 「全部隐藏 / 全部锁定」是**临时查看**开关，不写进谱面，关掉工作台自动复原

**其他**

- 每格打拍器音量（`SetHitsound` / `SetHoldSound`）按谱面取值播放

## 尚未完成

- **参数栏仍缺少数类型**：`FilterProperties`、`List`、`Note`、`Rating`、`Array`、`Export` 等仍显示为「暂不支持」

## 联机做谱

工作台顶部有「联机」按钮。**不搭服务器**——一人当主机，其他人直连，
只有主机需要配内网穿透。

**基本用法**

1. 填名字。所有人共用同一个「端口」框，默认 **21587**（和 Minecraft 有默认
   端口一个意思）——不改就用它，要改两边一起改
2. **主机必须先打开一张谱面**，再点「开房」——加入的人要拿你的谱面和
   它用到的音乐、贴图，所以开房前得有内容可拿。没打开会直接提示
3. 主机：把面板显示的监听端口配到内网穿透上
4. **其他人可以直接加入，不用先打开谱面** —— 加进来会自动拉取房主的谱面
   并打开它（连音乐和贴图一起）

> **所有人必须用同一版本的 AES。** 握手时会交换协议号，对不上直接拒绝、
> 并说明是谁的版本旧了。这比放进来更安全 —— 不同版本对同一个字段的理解
> 可能不同，连上之后消息照样收发成功、画面也正常，只是**写进去的值不对**，
> 而且双方都察觉不到。

**加入者的谱面写在哪**

加入房间时，会在**你自己那张谱的旁边**生成一个副本
（`xxx.aes-session.adofai`），之后你的所有改动都写进副本——
**你原来那份文件全程不动**，退出联机或关掉游戏时副本自动删掉。
所以「房主的谱」永远只有房主一份，你这边不留残留。

> 副本只能放在谱面**同目录**，不能放系统临时文件夹：ADOFAI 的音频和
> 装饰物贴图是按谱面所在目录解析的，挪走会让预览没声音、贴图全丢。

**掉线**

**连接断了不会把你踢出房间。** 网络抖一下、穿透隧道重连，都只会在面板上
出一条提示，会话原样保留：对面回来了，数据照收照发。

之前是「一断就回到未联机」，那意味着任何一次抖动都会把整个房间关掉。
更糟的是它还配了一条**自动判死**：20 秒没收到任何数据就认定对方掉了——
而两个人安安静静做谱时连接上一个字节都没有，于是**谁闲着谁被踢**，
刚连上不动手，20 秒后就掉。

现在改成：

- 主动点「断开」会**明确告知**对方，对方立刻清理（从成员表拿掉、通知其他人）
- 连接**断掉**则不清理、只提示，等人回来

**两个人同时改同一个值会怎样**

**后改的覆盖先改的，没有提示。** 这是刻意的，不是漏掉了检测。

做合作谱时大家各管各的段落，两个人同时改**同一个事件的同一个键**本身
就很少见。为这种少见情况，让每个人每次编辑都先走一次网络往返取锁，代价是
**每一处输入都慢半拍**；更关键的是锁会让**别人**看着你的界面变红、改不动，
而对方并不知道你在改什么、还要改多久。做谱需要随时互相帮改，一块被别人
按住、自己连碰都不能碰，比偶尔被覆盖更难受。

覆盖是可恢复的（撤回、或者让对方重发一次）。所以选可恢复的那个。

> 早期版本有过事件锁（选中即占用、别人变红改不动），已移除。


**加入时有一块黑屏加载页**

加入房间时整个界面会变黑，显示「下载谱面中 → 下载媒体 12/976」和一条进度条。

原因不只是好看：加入过程要处理的东西很多，中间态是「装饰物少一半、
**文字装饰物不见了**」——用户会以为坏了。现在这些中间态都在黑屏底下发生，
结束时**整体重建一次工作台**，那些没自动刷新上的东西就都正常了。

（重建是必须的：**文字装饰物在谱面重载后不会自己重新显示**，
重进一次工作台才正常——加载页正好把这一步藏起来。）

**音乐和贴图也会传**

谱面文件本身只存**文件名引用**（`"songFilename": "歌.ogg"`、装饰物的
`"image": "贴图.png"`），真正的音频和图片是**谱面目录里的独立文件**。
所以光传谱面文本，对面会是「没声音、没贴图」。

联机时：

- 收到谱面后自动检查自己缺哪些文件，缺的向主机要
- 主机把文件发过来，落在**你自己的谱面目录**里（游戏就是按这个目录找的）
- 收齐后自动重载一次，贴图和音频立刻生效
- 面板上会显示「正在接收媒体 3/7」
- **只传缺的**，已有的不重传

实测一首歌 + 几张图约 7MB，一次性传完，之后不再传。

> **成员目录里的媒体传不到别人那里。** 星形拓扑下所有媒体都由主机中转，
> 所以做谱时**媒体应该由房主统一持有**。成员本地加的音乐/贴图，房主那边
> 没有，别人也就拿不到。

**同步：全是自动的，没有「推送」按钮**

| 改了什么 | 怎么同步 |
|---|---|
| 参数值（输入框、开关、枚举、颜色） | 增量，**即时**（几百字节） |
| 时间轴上拖事件块 | 增量，即时 |
| **撤回 / 重做** | 增量，即时（撤回报的是被恢复的旧值） |
| 装饰物显隐 / 锁定 | 增量，即时 |
| **增删事件、拖装饰物** | **整份重推**，0.5 秒合并窗口 |
| 进入房间 | 自动拿到房主的谱面 |
| 谱面引用的音乐 / 贴图 | 自动传缺的那些（分批，一次性） |

改值方面还有一层：如果对方改的正好是**你当前选中在看**的那个事件，
你的参数栏会刷成新值，而且你正在打字的输入框和光标位置会一起还回来，
不打断你。这一步是必须的 —— 面板显示旧值、谱面里是新值的话，
你照着旧数字继续改就会把对方覆盖掉。

**不会弹任何确认。** 房间里两边谱面不同是常态（成员从进房起就在会话副本上
干活），每次都问等于每次都要点一下。

**唯一会分叉的情况**

增删事件没法增量同步（事件没有稳定下标），只能整份重推。如果**两个人在
很短的窗口内各自加过事件**，后推的那份会盖掉先推的 —— 谁都不含对方那一笔，
而且**没法自动合并**（要正确合并得做真正的差异合并，那不搭服务器做不到）。

万一分叉了，点「重新同步」拿房主那份覆盖回来。**这是留那个按钮的唯一原因。**

还有一道保护：**两边事件下标对不上时，改值会被直接拒绝**，而不是按下标硬写。
因为错位下标**依然有效**、只是指向了另一个事件 —— 不拦的话会安静地改坏
别人的谱面，而且双方都收不到任何提示。

**注意**：游戏原生编辑器也是改谱入口，从那边改的改动本功能看不到。

## 已知问题

- 关闭工作台后，游戏原生编辑器的事件特效可能滞后一拍（求值器直接读取事件数据，不驱动原生特效）。进入游戏播放时会自动重建
- 求值器与游戏的 DOTween 会争同一批格属性。已接管 位置/旋转/缩放/透明/辉度 五条通道；若后续发现别的通道被改回去，同法补进 PreviewEase.TakeOverChannel
- ShakeScreen、粒子等域在极端参数下未做充分回归
- 与 PACL2 共存时，工作台内的撤销只覆盖工作台自己记录的操作；原生面板里做的改动请继续用游戏原有的撤销路径

- **0.28.0** —— 一件大的、一件小的：往回拖播放头时**轨道不还原**，以及播放时**音乐与拍子对不齐**。
  - **往回拖：慢拖正常，快拖和瞬间点击不还原。** 这一条查了很久，最后是架探针把**场景里每一格**的四条通道逐格量出来才定位的。实测往回拖到 t=1.8、球已经回到第 1 格，场景里仍有 **96 格停在 `opacity = 0`**，而位置 / 旋转 / 缩放 / 渲染器 / 物体激活全部正常——所以"走过的格子大部分没还原"其实是**透明度**没被写回来，和位置无关。
    - 根因是 `AnimateTrack` 域里一条兜底判据写错了。原版的消失 tween 是一次性的，跑完就把格停在 `opacity 0`；播放头往回跳时那些消失段的 `Start` 落在播放头之后，求值循环第一句就 `break` 掉，于是**没有任何写入者**把格写回可见——而 `MoveTrack` 的 `RestoreBaseline` 刻意不恢复透明度（注释写明"透明度是 AnimateTrack 域的通道"）。

    - 改法是换判据：看的不是"有没有段开始"，而是**有没有已开始的段在主张透明度这个通道**（散开段和落回段都不带透明度，只有消失段带）。没有的话就显式写回 1。同时补上让位规则：`MoveTrack` 这一帧也在写这一格时本域不插手，否则会把 `MoveTrack(opacity 0)` 那种"藏在后面的格"又点亮。

- **0.27.0** —— 两处轨道位移的修复。都是先在求值器上架探针、把逐帧决策量打出来定位的，没有一处是靠读源码猜的。
  - **成组移动的轨道，球不跟着走**。原生 `positionOffset` 里的 `null`（解出来是 `NaN`）含义是**「这个轴别动」**：`ffxMoveFloorPlus.StartEffect` 对 NaN 的轴**根本不建 tween**，那条轴保留上一条 tween 留下的值。而求值器把每个事件的 target 初值取成了**烘焙位置**，于是「目标轴」写对、两个轴都留空的轴却被按回基线——一条 `positionOffset: [null, null]`（作者只拿它改透明度或旋转）的事件会把同一格上**前面事件刚推开的位移整条抹平**，`duration: 0` 时缓动比例恒为 1，抹得干干净净。Dream Flower 第 390 格那条 `range=0..389` 的就是它：实测 t=120.8 一到，365 那一组（12 格一起横移 20.5 格）的位移集体弹回烘焙位置。改法与装饰物域、相机域一致——那两处早就按「NaN 轴保留携带值」写了，只有轨道域漏掉。
  - **有全轨道 `AnimateTrack` 的谱上，`MoveTrack` 推开的轨道不显示**。`ffxFloorAppearPlus` 给**每一格**建一条 appear tween（连 `Fade` 这种只该淡入的也有一条，它无条件 `DOMove(floor.startPos, duration)`），而求值器的「落回正常」段也声明了位置。差别在生命周期：原生那条 tween 跑完就结束、**释放通道**，之后 `MoveTrack` 的 tween 才接管；求值器却让跑完的段**每帧继续写**，它排在 `MoveTrack` 之后入队，于是把位移抹回烘焙值。Dream Flower 第 174 格就是这么不动的（探针实测同一帧两笔写入：`MoveTrack` 写 `-36.6213`，其后一笔又写回 `-35.1213`）。
    - 修法是补上早先定义好、却从没被读过的 `PersistAfter` 语义，并按原生 tween 的存活规则重新分配**通道归属**：只有**最后启动的那一段**、和标记了终态的消失段才主张通道。只让「最后启动」这一段主张，是为了不重蹈早先「跑完松手」的坑——那时 `Duration=0` 的散开初态又开始主张，格永远卡在散开。
    - 跑完的 appear 段还要**让出位置**，但只在「这一帧确实有别的域在写这一格的位置」时让。一律松手的话，拖动播放头整个跨过某格动画时，那一帧没有更早的写入打底，格会永久停在散开初态。
    - 旋转 / 缩放 / 透明度不让：`settle` 段这三个通道的目标值就是烘焙值本身，和 `MoveTrack` 非位移事件写的是同一个数；而透明度是全局消失动画的通道，必须保持「后写者胜」，否则已经淡出的格会被写回来。
    - 顺带把「这一格有没有人写位置」从线性扫队列换成 HashSet：AnimateTrack 每格每帧都要问一次，线性扫会退化成 O(格数²)。
- **0.26.0** —— 把最后两类没建模的格子补齐（三球、freeroam），并修掉一个一直靠巧合站着的角度公式。这几处同样是先架探针取原生逐帧数据、再照着改。
  - **播放时音乐和拍子对不齐（几十毫秒，每次不同）**。根因是**音频的起播时刻会被量化到音频缓冲区边界**（44100Hz 下 512 采样 ≈ 11.6ms），每次落在一个不同的倍数上——实测满量程 ±46ms，且修正量几乎全是 11.6ms 的整数倍。这也解释了为什么"暂停再播放"往往能把它掰回来：重新起播 = 重新落一次量化点。
  - 修法是**起播 0.6 秒后自动量一次、把偏差 seek 掉**。有两个必须守住的点，早先的失败都栽在这里：采样必须等音频**真的在播放**（倒计时期间 `song.time` 恒为 0，算出来的期望值是负的），以及**绝不能对"已排程未播放"的 AudioSource 写 `.time`**（那会破坏排程，音频干脆不按计划起播）。
  - 画面完全不碰：音乐对齐的是谱面的拍子，画面本来就跟着谱面走。补偿后残余在 5ms 以内，不需要手动干预。
  - **多行星（三球）支持**。`MultiPlanet` 事件把球数在 2..3 之间切换。以前 `PlanetCount != 2` 的格整块跳过，因为求值器是对**活的 `planetList`**（8 颗球：红蓝 + 6 颗给多球格准备的克隆）步进的，第 N 格算出的是 `planetList[N % 8]`，只有 N%8 是 0 或 1 时才碰对。现在照原生编辑器 `ScrubToFloorNumber` 的做法在 `Analyze` 里预计算：先把列表收成两颗、逐格步进，遇到球数变化就重排（**变多 = 新球插在当前这颗的位置、变少 = 删它前面那颗**），中途旋转格反向。新球恒为 `planetGreen`（原生从 `availablePlanets[0]` 取，那串队首就是它）。
  - **三球的位置**：实测三颗永远构成边长 = `cosmeticRadius` 的正三角形——选中的那颗停在格心（逐帧量到距离恰好 0），另外两颗在相对角 `0` 和 `−π/3` 上。原生那段多边形公式按着展开得到的是 1.38R 上的点，和实测形状对不上，所以以实测为准。
  - **三球格的角度**：起步角多一项 `IAPB(numPlanets)·方向`（`π(n−2)/n`，双球是 0 所以一直看不出来），第三颗的配色走原生的 `ApplyMultiplanetColors`（按对象名上色，`planetGreen` 才是绿），球数收缩回 2 时那颗按原生播放的方式 `Die(0.3f)` **爆炸消失**。
  - **freeroam（自由移动）支持**。网格格不住在 `listFloors` 里（求值器快照的来源），所以单开一个域直接驱动 `lm.listFreeroam`。补做了原生只在**进播放时**才跑的 `ColorFreeroam`（把生成格染成入口格的颜色、并把入口格本体藏掉）——求值器不调 `Play()`，这一步以前从来没跑过。
  - **freeroam 里球是输入驱动的**，时间轴上不可复现；实测没有输入时原生就是"球停在入口格中心、角度按每拍 π 原地转"。以前整格跳过、连角度一起停，看起来是"卡死"。
  - **freeroam 出场**（结束前 `outTime` 拍开始）：其他格一拍渐隐；球那格飞到下一格的入口边缘（`outEase`）；`outCam` 时相机按 **Tile 模式**平移过去，并且**把 zoom 设成 1**（原生 `MoveCameraToTile` 的 zoom 参数就是 `1f`，不是"保持当前"）。球是骑着那格走的。
  - **出场时球的角度会被重设**成 `nextfloor.entryangle − π·方向 − π·outBeats·方向`，同时起一条 cosmetic 把重设那一瞬的视觉接过去、一拍内衰减到 0。这两半必须成对：只加 cosmetic 不重设硬值，渲染角会当场跳掉一整份（表现为"进倒计时突然差 180°"）。
  - **暂停格的扫角公式一直是错的**。以前写 `sweep = π*(1+extraBeats)`，那等于**假设该格走完自身角度恰好 1 拍**。原生这一段是「走完该格角度的时间 + `extraBeats` 拍」。180° 的暂停格恰好满足那个假设（所以 NYA 那张谱一直没暴露），**270° 的格就差半圈**——实测某谱第 10 格原生扫 2π、AES 只扫 1.5π，球"还差一点角度就突然落地"。改用 context 里现成的 `floorTravelAngle`（每拍 180 度）算，拍数自动对上。
  - **停着的那颗球以前根本没写角度**。原生每帧推进角度的**只有 `isChosen` 那颗 = 停着的那颗**（`Update_RefreshAngles` 只对它跑）；飞的那颗自己的 `angle` 是旧值，只有位置是被算出来的。求值器以前写反了（只写飞的那颗），于是停着那颗的朝向停在**上一格**的值上，落地一交换就差半圈。
- **0.25.0** —— 行星与镜头：把长按那一段还原。这一版的三处修复都是先架探针取到原生的逐帧数据、再照着改的，不是照源码解读猜的。
  - **双球"谁停在格上、谁在飞"算错了**。`planetList` 里有 **8 颗球**——`planetRed`、`planetBlue`，外加 6 颗给多球格准备的克隆（全停在原点、`currfloor` 为空）。求值器以前是对这个 8 元环步进的，于是第 N 格算出的是 `planetList[N % 8]`：只有 N%8 恰好是 0 或 1 时才碰对，其余格子上两个角色整个错位。长按上看得最清楚——该绕转的那颗被摁在滑移线上直着往前推。改成照原生编辑器 `ScrubToFloorNumber` 的做法：它先 `SetNumPlanets(2, planetList[0], 0)` 把列表**收成两颗**再步进，而收成两颗之后 `next`/`prev` 指向同一颗，步进就退化成按格数奇偶交替。顺带把"每帧把全部 8 颗都摆到圆心上"和"给全部 8 颗都开环"两处也收成只动那两颗。
  - **长按线走完不变色、拖动时一直闪**。`scrHoldRenderer` 有**自己的 `Update`**，每帧最后一句按 `holdCompletionEased` 重刷填充进度；而求值器只写过 `holdCompletion`——那个字段只在 `scrPlanet.Update` 里写，而预览期间 `scrPlanet` 是关掉的，于是它冻在关卡加载时的 0。每帧两个写入者抢同一个材质参数：拖动时指针不动的帧求值器不重算、线被擦回 0，一动又填上（一直闪）；播放时求值器的写入总被覆盖（看不出变色）。两个进度字段一起写之后，原生那一下写的正好是我们想要的。
  - **长按里球少了那层小幅摆动**。原生在滑移上还叠了一层 `addBob = tileSize * 0.1 * Vector2.one * sin(angle - exitangle)`——注意它是沿**对角线**摆、不是垂直于长按线，幅度 0.1×tileSize，且只在 `holdDistance > 0` 时生效。原版里那颗球走出的"波浪"就是它。
  - **长按期间镜头不跟**。原生 `scrCamera` 的跟随目标是 `topos + offset + holdOffset`，其中 `holdOffset` 由行星的长按分支每帧 `camy.SetHoldOffset(holdOffsetPos)` 写入——所以相机是**跟着球一起沿滑移线走**的。求值器以前恒用"球进这一格时的位置"，滑移线长 5 格时整段相机原地不动、球已经滑出画面。另外修了落地下一格时相机回跳：预计算跟随轨道的那条递推还在朝旧目标推进，和逐帧求值走了两个不同的答案，现在两处合并成同一个采样函数。
